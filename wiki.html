Introduction

JettUnified is a modular survival plugin for Paper. It bundles 21 modules (teleportation, kits, teams, economy, TAB, moderation, admin tools and SMPCore gameplay rules) into one plugin.

This wiki covers installation, the main config files, every module, and the full command and permission lists.

Tip: use the search box on the left to filter topics. Every config shown here is the default file shipped with version 1.0.

Installation

  1. Check your server: Paper 1.21.x (1.21.1 or newer) with Java 21, or Paper 26.3 with Java 25.
  2. Download the jar for your version.
  3. Put it in your server's plugins/ folder.
  4. Start the server. JettUnified creates its config folder and the SQLite database.
  5. Edit plugins/JettUnified/modules.yml to choose your modules, then run /ju reload.

Optional plugins

  • LuckPerms: rank prefixes in TAB, group formatting and /rankinfo.
  • Vault: lets shop plugins use the JettUnified economy.
  • PlaceholderAPI: use any PlaceholderAPI placeholder in TAB and the scoreboard.
Shop plugins: JettUnified loads before EconomyShopGUI so the economy is ready when the shop starts.

Each module keeps its own config.yml and messages.yml, so you never have to scroll one huge file.

modules.yml

This is the main switchboard. Set a module to false and run /ju reload. The module unloads and its commands are removed, without restarting the server. You can also open the Module Manager GUI with /ju modules.

modules.yml

  debug: false
  language: en
modules:
  spawn: true
  homes: true
  warps: true
  back: true
  tpa: true

The luckperms-rank-support block controls the Rank Display module. If LuckPerms is not installed, it does nothing.

Storage

JettUnified needs no database server. Economy balances and teams are stored in an SQLite file that is created on first start. Homes, warps, kits and other module data are saved in YAML files inside each module folder.

storage.yml
# JettUnified storage.
# SQLite is the default and needs no setup. The database is created automatically.
# Keep the database on a local disk, not on a network share.
storage:
  type: sqlite
  sqlite:
    file: data/jettunified.db
# MySQL is reserved for networks and is not enabled yet.
  mysql:
    enabled: false
    host: localhost
    port: 3306
    database: jettunified
    username: root
    password: ""
    use-ssl: false
  • YAML files are written to a temporary file first and then swapped in, so a crash during a save can't leave a half-written file.
  • If SQLite is not available, economy and teams fall back to YAML.
  • /ju storage migrate moves old YAML economy data into SQLite.

Spawn, Lobby, Homes, Warps & Back

All teleport modules share the same pattern: a delay (cancelled if the player moves), and a cooldown between uses.

Homes

Players get 3 homes by default. Give jettunified.homes.unlimited for no limit.

modules/homes/config.yml
homes:
  max: 3
  overwrite-existing: false
teleport:
  delay: 3
  cancel-on-move: true
cooldown:
  enabled: true
  duration: 10

Warps

Warps are admin-only by default. Set player-warps.enabled: true to let players make their own, up to the limit. jettunified.warp.admin sees every warp.

modules/warps/config.yml
teleport:
  delay: 3
  cancel-on-move: true
cooldown:
  enabled: true
  seconds: 10
player-warps:
  enabled: false
  max: 3

Back

Saves your location before death and before teleports. SMPCore Combat can block /back after a PvP death.

modules/back/config.yml
teleport:
  delay: 3
  cancel-on-move: true
cooldown:
  enabled: true
  seconds: 10
save-on:
  death: true
  teleport: true

TPA

Teleport requests between players. Requests expire after 60 seconds. Players can block requests with /tptoggle.

modules/tpa/config.yml
request:
  expire-seconds: 60
teleport:
  delay: 3
  cancel-on-move: true
cooldown:
  enabled: true
  seconds: 10

RTP

Random teleport within a radius around the player. It skips water, lava and leaves. On busy servers, pre-generate the world and set only-generated-chunks: true. Staff with jettunified.rtp.bypasscooldown skip the cooldown.

modules/rtp/config.yml
cooldown:
  seconds: 300
teleport:
  delay: 5
  cancel-on-move: true
search:
  max-attempts: 50
  only-generated-chunks: false
radius:
  min: 500
  max: 5000
avoid:
  water: true
  lava: true
  leaves: true
effects:
  sound: true
  particles: true

Kits

/kit opens the kit menu. Players can preview a kit before claiming. Kits locked behind a permission show in the Ranked Kits menu. The permission is jettunified.kits.<kit>.

Admin subcommands

CommandWhat it does
/kit create <name>Create a kit from your inventory
/kit edit <name>Edit a kit in the GUI
/kit delete <name>Delete a kit
/kit give <player> <name>Give a kit to a player
/kit preview <name>Preview a kit
/kit reloadReload kits

Cooldowns are saved in the database, so they survive restarts.

Economy

JettUnified stores balances itself. Vault is optional. With Vault installed, JettUnified registers as the Vault economy provider so shop plugins can use it.

modules/economy/config.yml
enabled: true
currency-format: "$%amount%"
decimals: 2
starting-balance: 0.0
currency-name: "Dollar"
currency-name-plural: "Dollars"
vault:
  register-provider: true
  override-existing: false

Placeholders: %player_balance%, %balance%, %player_balance_formatted%, %balance_formatted%, %currency%, %currency_name%, %currency_plural%.

Ender Chest, InvSee & EcSee

/ec opens your own ender chest. It can be 27 or 54 slots. Staff can open other players' inventories with /invsee and ender chests with /ecsee, including offline players.

modules/echest/config.yml
size: 27
modules/invsee/config.yml
allow-self-invsee: false
allow-offline-inspection: true
gui-title: "Inventory of <player>"

Custom Recipes

/cc (or /customcrafting) opens the recipe editor. Put the ingredients in the grid, set the result and save. Recipes work right away, with no restart.

/cc delete <name>Delete a recipe
/cc listList recipes
/cc disablerecipe <id>Turn off a vanilla recipe
/cc enablerecipe <id>Turn a vanilla recipe back on
/cc disabledList disabled vanilla recipes
/cc reloadReload recipes

  - "mace"

SMPCore

SMPCore is a set of gameplay rules for survival servers. Open the manager with /smpcore. Each feature has its own file in modules/smpcore/SmpCoreModules/ and its own switch in modules.yml.

Potion Limiter

Block any potion in normal, long and strong forms. It also blocks splash, lingering and tipped arrow versions. Click a potion in the menu to toggle it.

Enchant Limiter

Block an enchantment or set its max level, including mace enchantments. Bypass items work by item type. Certified items bypass all limits with a hidden ID on that one copy.

Combat

Combat timer (20 s by default) with optional combat-log kill. You can block commands, teleports, ender pearls, riptide, elytra, totems in combat and /back after a PvP death.

World Rules

Over 40 switches: portals, explosions, mob spawning, villager trading, fire spread, water and lava flow, raids, weather, natural regen, fall damage, PvP and workstation blocks.

Quality of Life

Auto-smelt, tree capitator, vein miner, double doors, silk-touch spawners, auto pickup, death chests (15 min expiry) and crop replant.

Block Item

Remove listed item types from the server with a warning. Certified items are still allowed.

Cooldown Control

Add an extra use cooldown to any item type, up to 300 seconds by default.

Item Limits

Set the most of an item type a player can carry. Main inventory, hotbar, offhand and armor all count.

Moderation

Bans, temp bans, IP bans, mutes, jails and warnings. Data is kept in the database. Ban screens show your appeal link.

  • Time format for temp bans, mutes and jails: s, m, h, d, w, mo (month), y. You can combine them, like 1d12h.
  • Jailed players can only move within a small radius and cannot use teleport or message commands.
  • Muted players cannot use /msg, /tell, /r and similar commands.
modules/commands/config.yml (moderation part)
appeal-link: "discord.gg/yourserver"
console:
  hide-multiline-disconnects: true
jail:
  enabled: true
  movement-radius: 1
  protection-radius: 2

Admin Tools & Utilities

Each admin tool can be turned off on its own in modules/commands/config.yml with <command>.enabled: false. Utilities include portable workstations, /repair, /condense and game mode shortcuts.

Power tools: bound commands run with raised permissions. Only give bound items to players you trust. By default players also need jettunified.powertool.use.

FAQ

Do I need to restart after changing modules.yml?

No. Run /ju reload. Disabled modules unload and their commands are removed.

Do I need Vault?

No. /balance, /pay and placeholders work without it. Install Vault only if another plugin, like a shop, needs to use the economy.

Can I use it with EssentialsX?

Many commands overlap. Turn off the JettUnified modules you don't want, or turn off the matching Essentials features, so only one plugin handles each command.

Where is my data?

Economy and teams are in plugins/JettUnified/data/jettunified.db. Other data is in the YAML files in each module folder. Use /ju storage backup to back up the database, and copy the whole JettUnified folder for a full backup.

Is vanish available?

Not in 1.0. The vanish system is paused and will come back in a later update.
